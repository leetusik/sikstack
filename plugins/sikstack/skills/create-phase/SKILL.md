# create-phase

Turn an operator request into one or more phases, or an agenda or its item, with their intent captured first. **This skill creates phases; it never decomposes or implements them** (that is the `DECOMP` slice's job, later).

**Who may invoke it.** The operator, or the agent when instructed (an approved plan or a direct operator instruction says to create a phase). **Never on the agent's own initiative.** Whoever started it, `phase new` runs only after the operator explicitly confirms each phase's name and objective. **Invocation is not the gate; confirmation is.**

## Procedure

1. **Refine.** Restate the request plainly; read only the `.sikstack/docs/current/` sections it touches and `next` if useful. Keep the operator's exact words. **From an agenda** (`/create-phase A7-m3`): take its title, note and open items (`agenda-show <AID>`) as the request; every `phase new` it runs takes `--agenda <AID>`. **From the Open agendas** (`/create-phase open agendas`, or bare with no request): *The open-agendas route*.
2. **Clarify.** Ask about anything unclear (scope, one phase or several, name and objective, now or later) and wait. Run no `sikstack` command yet.
   - **Visual design:** ask the design style, with your suggestion and its reason (the `design-cowork` skill): `build-after` (one phase; the whole design lands, then `DECOMP2` cuts the build), `design-only` (a design phase, then a separate apply phase; it must be chosen here, since `DECOMP` cannot run `phase new`), or `paired` (design 1 → apply 1 → …, no `DECOMP2`). Say how it runs: each design is drafted in the product repo's design folder on the product's own components, built and served at a local URL you click through, and signed by your words in the session; applying it is a later slice that moves its files into production. And suggest the drafter: `fable` when the design sets a look (a new face, a redesign, a landing), `opus` when it applies a settled look; Fable costs about twice per draft. A critic runs only if the operator asks for one.
   - **An explain** ("explain P30", "write a book on X"): not a phase. Hand it to `/sikstack:explain`, which writes in the session.
   - **A full regression sweep** ("QA sweep", "re-run the checklist"): *The QA-sweep route*.
3. **Confirm.** Present each phase's **name** and **objective** (a new agenda: title and note; an item: its agenda and body). For a phase that changes product files, also propose its branch name per repo it will change, from `repo convention [--repo <name>]` (at root, the repo's habits), with no phase or slice IDs. **One question rides on that confirmation, never a stop of its own:** when `next` lists `pr_open=` or `pr_stack=`, or the operator names an open PR, ask whether the phase builds on one, and propose its branch as the base (`${CLAUDE_PLUGIN_ROOT}/skills/pr/reference/stack.md`). Never split a phase for size: a large one splits into PRs at its review. Wait for the explicit yes.
4. **Route on the operator's choice.**
   - **Not now:** fix it now, drop it with a reason, or (the exception) an item on its agenda that says what would make it actionable. Closely related to an existing agenda (`agenda --json`): an item on it, never a new agenda and never a deferral: `sikstack agenda-item add <AID> --kind note --author person:<the operator> --source <where> --body "..."`. Only when no agenda is closely related: `agenda-add --title "..." --author person:<the operator> [--note "..."]` (the operator's own is Open at once; the engine mints the id). Commit, report, STOP.
   - **Make a phase**, for each in the confirmed order: `sikstack phase new --name "..." --objective "..." [--agenda <AID>]`; use the id it prints. It creates only `DECOMP` and `REVIEW` and scaffolds `intent.md`. Fill `intent.md`: the request word for word under *Original Input (verbatim)*; the confirmed wording under *Confirmed Intent* (what the operator wants, never workflow mechanics); the Q/A under *Clarifications Resolved*; for a phase that changes product files, a `Branches:` line (`Branches: <name>`, `Branches: <repo>: <name>; …` on a multi-repo host, `Branches: feat/y (base: feat/x, merges after #12)` when stacked; `DECOMP`'s end records them with `pr branch`); for a visual phase only, `## Design Style` with the style and its reason, then `Drafter: fable` or `Drafter: opus` (an older `Mockup:` line is ignored).
   - **Say nothing about worktrees.** The phase runs on this stream. When `phase new` prints a hint that it could run on its own branch: Relay that hint; never act on it. Only the operator's word starts a worktree, later, in `/do-next-slice` or `/do-whole-phase`.
5. **Commit, then STOP and report.** Commit only what the intake wrote (the new phase or job folders and the regenerated `.sikstack/works/` files), in one commit by the `commit` skill (`${CLAUDE_PLUGIN_ROOT}/skills/commit/SKILL.md`, read by path): `chore(P<N>): create <name> and record the operator's intent` (an agenda or item: `chore(agenda): add <title>`), then `git -C .sikstack …` for the state. In a linked checkout (`next` prints `store=cloud`), skip this commit: sikstack's revisions are the workflow's history. Product commits are unchanged. Never push. List what you created and stop: no decomposition, no `plan.md`, no code.

## The open-agendas route

`/create-phase open agendas`, or bare with no request. **List** from `agenda --json` the agendas with `shown_status` `Open` (`In progress` has a live phase) and `items_open` above 0; skip Proposed ones (accept them first, `/agenda`). **Propose one phase per agenda**, its objective from its open items (`agenda-show <AID>`); group two only with a stated reason. Confirm each name and objective by step 3 (the gate), then `phase new ... --agenda <AID>` by step 4, `intent.md` listing the open items as its scope (a grouped phase links one and names the other).

## The QA-sweep route

A review re-runs only the `## Regression Checklist` lines inside its phase's boundary, so the whole list is re-run only when the operator asks. An ordinary phase through the procedure; objective: *"re-run every `## Regression Checklist` line in the manifest runtime and report what no longer holds"*. Write into `intent.md` what its `DECOMP` will cut: `--kind qa --risk low` slices, one per checklist block; no product code, so its gate is normally waived.
