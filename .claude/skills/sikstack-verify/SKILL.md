# Verify sikstack in a browser

One script, `run.sh` (beside this file), runs the whole product on loopback without touching the checkout; one file per feature in `features/` says how to reach it, drive it and prove it. A playbook: leave it with a stated reason when the task needs something else.

1. **Doctor** — `bash .claude/skills/sikstack-verify/run.sh doctor` (from `platform/`; any cwd works). Checks Docker, uv, pnpm, node, `web/node_modules`, `.venv`, `playwright-cli` (installs `@playwright/cli@0.1.25` when missing), this checkout's `next dev` lock and ports 3030/8766/3061. A `next dev` already running in this checkout's `web/` (often the operator's own `pnpm dev`) blocks the run, whatever its port: Next 16 allows one per `web/`. Doctor names it; stop it, or run the skill from another worktree. A port taken by anything else (another checkout's dev server, say) is named and left alone; `up` takes the next free one.
2. **Launch** — `run.sh up [evidence-dir]`: a `postgres:17` container, migrations, the API (scratch `KB_ROOT`, `KB_GIT_COMMIT=false`, `KB_PUBLIC_BASE_URL` the web's address), a local test account, the API again with `KB_INSTALL_FEEDBACK_PROJECT_ID` naming its project `sikstack` (where the sikstack plugin's install Feedback lands), the design origin (`server.design_serve`, each published design build at `<build>.design.sikstack.localhost:<port>`), `next dev`. The app is reached at `http://sikstack.localhost:<port>`, never `127.0.0.1`: the app and the builds are then same-site on different hosts, as in production (Chromium resolves every `*.localhost` name to loopback). `SIKSTACK_VERIFY_WAITLIST=1 run.sh up` turns the sign-up waitlist on, as production has it (the test account is approved already; `signin other` approves the second account it makes, with `python -m server.waitlist approve`). Every process starts from a scrubbed environment: no vendor API key (`GOOGLE_API_KEY`, `GEMINI_API_KEY`), no `KB_SMTP_*`, no operator account, whatever your shell exports, so nothing is billed and no mail leaves. No `web/.env.local` is written. Then `run.sh signin` (a saved sign-in is reused; the BFF allows about 5 logins per 15 minutes). `up` and `run.sh status` print the web URL, the evidence folder, the browser session's name and what runs.
3. **Drive** — `playwright-cli -s=<session> <command>`, with the session name `up` printed (`sikstack-verify-<id>`), called plainly (no `cd … &&`, no env prefix): `goto`, `snapshot`, `find "<text>"`, `click`/`fill` with a ref or a selector such as `'role=button[name="Send"]'`, `screenshot --filename=<evidence>/<name>.png`. `run.sh expect "<text>"...` waits until the page shows each text and fails otherwise. Never type the password yourself, and never `kill-all`/`close-all` (other sessions may be running).
   **On a phone or a tablet's WebKit** — `run.sh webkit phone|tablet <path> [name] [measure.js]` opens one page of the stack in WebKit 18.2 (Safari 18.2, as iOS 18 draws; playwright-core 1.49.1, WebKit build v2104, installed once under `${TMPDIR}sikstack-verify/webkit-1.49.1/` and the Playwright cache) with the `iPhone 13 Mini` profile (375 wide, @3x) or the `iPad Mini` one (768), signed in, shoots it full-page into the evidence folder (`<name>.png`, default `webkit-<device>-<path>.png`) and prints one JSON line: the engine, where it landed, the width, whether the page scrolls sideways, the rail's height, and `measure`, the value `measure.js` (a function body run in the page) returns. Use it for a change to how a page lays out on a phone: Chrome and playwright-cli's own WebKit (Safari 27) draw some layouts an iPhone on iOS 18 does not (a grid whose `min(10em, 100%)` sits inside its own size container is 0 px wide there). The sign-in: WebKit never sends the `__Host-` session cookie (Secure) over plain http, where Chromium treats `*.localhost` as secure, so `webkit.mjs` adds the saved sign-in's cookies to the requests for the app's own origin only; a design build's host keeps its own cookie (adding them to every request breaks the design frames). A design build's frames are not seen this way: with a request route in place, this WebKit stores a build host's `sikstack_design` cookie but never sends it, and WebKit counts `sikstack.localhost` and `<build>.design.sikstack.localhost` as two sites (no public suffix), so a framed `/_open` cannot set its cookie at all; both give the 403 page, where production's `sikstack.com` and `<build>.design.sikstack.com` are one site and the frames show the build. Mobile WebKit has no `mouse.wheel`: scroll with `window.scrollTo` in `measure.js`.
4. **Evidence** — everything lands in the evidence folder (default `<home>/runs/<time>/`; a relative `evidence-dir` is made absolute): `run.log`, `api.log`, `web.log`, screenshots, `auth-state.json`, and the CLI's snapshots in `cli-output/`. Report the screenshot paths and the end state you saw.
5. **Cleanup** — `run.sh down`: closes this run's session, stops the processes `up` started (each server runs as its own process group, recorded at launch; `down` signals that group while its leader's pid and start time still match), removes the container it created with its volume and the scratch data, checks the evidence for the password, keeps the evidence. Anything else, even on a port the run used, is named and left alone. Always run it, also after a failure. After it: no container of ours, nothing of ours on the ports, `git status` unchanged.

**One run per home.** The home is `$SIKSTACK_VERIFY_HOME`, by default one folder per checkout under `${TMPDIR}sikstack-verify/`. The container (`sikstack-verify-pg-<id>`) and the session (`sikstack-verify-<id>`) are named after it, so runs from two worktrees (or two homes) go side by side, and one's `down` never touches the other's.

## Features

`features/<name>.md`: **Reach it**, **Drive it** (a ```` ```bash drive ```` block of the kept steps), **Proof**. Run one whole with `run.sh feature <name>` (log and screenshot in the evidence folder), or follow its steps by hand. Pick the file named after the surface the change touches; read only that one. Today: `sign-in`, `connect` (the connect page `/sikstack:sign-in` opens: ready with the account under Connect and "Use another account", `other` naming `/sikstack:sign-in release`, a `release: true` start freeing the install for a second account; ready and `other` shot at 1440 and 375), `overview`, `library`, `feedback`, `members` (`/members` with two accounts, the second joined through the API's invite: Make owner on a member's row, the row then Owner and Leave on the owner's own row, a sole owner's view with no Leave, and a co-owner leaving its only org for a fresh `default` one; shot at 1440 and 375), `design-service` (the Design list and viewer over published builds: a linked scratch checkout from `run.sh workspace <dir>`, a second account from `run.sh signin other`, share links, the size cap, `design-delete` and a build's script against the session), `design-local` (the same service from a local workspace: `run.sh local <dir>` makes an unlinked install whose phase worktree, cut before the link, gets its design link by `design-link` and a minted key; publish from the worktree and the main checkout, sharing turned on in the viewer, then a signed-out browser on the share link clicks every page and state at 1440 and 375, a modal closed by its own Cancel; run it after `design-service`, which counts its project's builds), `workspace` (the Agenda end to end against a linked scratch checkout, a sync between steps: feedback onto a new agenda and onto that agenda, a note and its author, the agenda's items, a Proposed agenda accepted and a non-member refused through `run.sh api other`, an item Done, a Split onto a new agenda, the last open item Done closing its agenda, Propose on the Agenda, the folded jobs' old addresses), and `design` (the static design build under `web/design/`: no `up`, its own steps).

**Add one** when a probe worked: copy the `playwright-cli` lines you ran (the CLI prints each as Playwright code), with `$WEB`, `$EV`, `$SESSION` and `"$RUN"` for the URL, the evidence folder, the session name and this script, end with an `expect` and a `screenshot`, and run `run.sh feature <name>` once before keeping it.
